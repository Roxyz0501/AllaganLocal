# Whole-application recheck — 2026-10-25

Version: 1.3.0.2. Scope: Allagan Local's history/storage/settings, price cache, purchase worker/CSV lifecycle, existing Web/API tests, menu navigation and responsive sales summaries. Tests used isolated synthetic records and ephemeral ports; the installed plugin, running production site and production history were not changed.

## Reproduced and corrected

1. **History recovery after losing a migration marker.** After importing legacy JSON and adding newer events, deleting the marker made the next startup compare the complete new journal against legacy-only event counts and reject it. Migration now verifies each immutable imported ID and complete stored contents, retaining subsequent events. Identical replay remains write-free at the event level; conflicting IDs fail explicitly. Original history files are preserved.
2. **A damaged backup blocked healthy setting saves.** A malformed older backup caused Web/native settings saving to fail even with a healthy current file. Both writers now stage the three newest valid generations, preserve malformed backups separately after a successful primary commit, and retain the existing single-writer/failure-limit behavior. A post-commit backup lock or failure can also be retried without rewriting the already committed primary. Staging paths are scoped to the current save so stale temporary files are not promoted.
3. **Purchase worker recovery race.** The old worker's later exit notification could clear the replacement worker and reject its new requests. Worker callbacks now verify ownership before changing shared request state.
4. **Purchase service shutdown/CSV completion.** Requests after close used to enter the pending map before failing, eventually reporting false queue saturation. They now reject before creating work. A CSV worker exiting with code zero before its result used to leave the reader waiting; it now reports failure. Closing the service rejects pending reads and wakes CSV readers.
5. **Disposable price cache corruption prevented startup.** Broken price SQLite/JSON files could stop the whole dashboard and leave a DB handle open. Validated cache loading closes failed handles, preserves corrupted cache files and sidecars, and creates a fresh cache. User histories and purchase DBs are never treated as disposable caches. Read/permission/locking failures are not mistaken for corruption.

The marker, malformed-backup and worker ownership/closed-service tests were observed failing against the previous implementation before correction. The corrupted SQLite case also reproduced its leaked-handle cleanup failure. New regression cases cover these paths, conflicting immutable history IDs and early normal CSV-worker exit.

## Limits

This is a targeted source review plus regression/integration/browser verification, not proof that every possible bug is absent. Native in-game rendering and real login/logout timing, live external-service rate limiting, real large-history migration, physical SSD writes and long-duration resource behavior remain unverified. Explicitly broad history ranges still incur work proportional to the selected records; disposable media quotas are enforced during their configured cleanup passes. No new recurring OS monitor or production migration was introduced.

# Whole-application recheck — 2026-10-26

Version: 1.3.0.3. This follow-up covers the previously released 1.3.0.2, with additional attention to overlapping UI requests, cached results, navigation and export consistency. All execution used synthetic records and isolated ports/directories. No production history, installed DLL or running production server was changed.

## Corrections

- A parent storage search could display the wrong results when returning to its cached query while another query was still pending. Cached reuse now cancels and invalidates the other request. Clear also invalidates pending results; an older failed request cannot overwrite a newer search's status.
- A currency request that recovered with unchanged data left its previous error visible. Successful responses now clear the warning before the unchanged-render shortcut. Late failures are guarded by the request generation.
- Currency CSV exports used live filter controls even while their displayed rows still belonged to the previous query. Exports now retain the query associated with the displayed response. Sales CSV query snapshots also update when a different query returns identical data.
- Leaving currency, sales or purchase views cancels pending search debounce timers. Currency and sales navigation also invalidates/aborts in-flight requests, preventing late responses from updating an inactive view. Existing purchase cancellation remains in place.

The storage-search race and currency error/recovery cases failed against the previous source before correction. Five added regression tests cover these cases, sales cancellation/export conditions and character numeric/tag sorting (zero, unknown, ascending/descending and sub-tag precedence).

## Verification

- 75 Web/API/history/valuation/storage/CSV/navigation/common-tab tests passed. This includes the existing JST date-boundary, exclusion, migration, backup-recovery and worker-lifecycle regressions.
- Native settings: 14 checks passed. Seven commits wrote 664 logical primary payload bytes, 664 temporary payload bytes and 1,406 backup-copy bytes; unchanged saves add zero commits. These are application payload counters, not SSD physical writes.
- Host lifecycle: 14 checks passed, including reuse, adopted restart, unexpected exit, explicit stop, plugin disposal, parent process exit and avoiding duplicate surviving servers.
- Localization: 680 checks; font lifecycle: 44 checks; Release build: zero warnings/errors. No translation keys or canonical templates changed.
- Headless Edge: 18 populated-server navigation/history/item-detail/CSV/list flows passed with one active menu item and zero uncaught JavaScript errors. External service calls were intercepted.
- Layout: 15 theme/viewport combinations passed (1920, 1280, 768, 390, 320 px), with aligned summary cards and no clipped amounts/counts or horizontal overflow. The narrow screenshot was visually inspected.
- Package validation checks the bundled runtime, browser modules, seven dictionaries, version/manifest URLs and exclusion of personal data.

The initial restricted test invocation could not complete local-server/filesystem checks and was stopped by identifying only its test process tree. The complete suite passed with the necessary test permissions; those environment failures were not treated as product regressions.

## Limits

This is a broad regression run plus targeted source review, not a guarantee that every possible bug is absent. Live-game rendering/login/logout timing, live Lodestone/market rate limits, production-scale migration, prolonged resource use and physical SSD writes remain unverified. The authorized independent server still survives game exit. No new OS task, monitor, production migration or installed-file replacement was introduced.

# Whole-application recheck — 2026-11-04

Version: 1.3.0.4. Reviewed history/valuation, exclusions, CSV pagination, navigation, storage rendering, persistence and host lifecycle. All execution used small synthetic records and isolated ports/directories. Production history, installed DLLs and the running production server were not changed.

## Corrections

- Mylist dashboard day changes used NPC values even when the list selected market pricing. The dashboard now applies the same historical pricing selection as the history view. Reproduced before correction: prior market value 200 and current value 700 showed an NPC difference of 35 instead of the correct market difference of 500. Switching back to NPC gives 35; exclusion gives zero and restoration returns 35.
- CSV pages now share revision checks covering current exclusions, catalog/character data, sales and market updates. Sales and currency responses also expose this revision. If the source changes during export, the existing exporter rejects the mixed snapshot instead of combining inconsistent pages.
- History dates are validated before reading partitions, including nonexistent calendar dates and reversed ranges. Invalid requests return a controlled 400 response instead of reading an invalid range or producing an internal error.
- Storage recovery with unchanged data now clears the previous warning without rebuilding the unchanged view.
- Navigation or closing an item detail invalidates pending detail responses. Late responses cannot open the old item on another page, and stale errors cannot display a toast. Explicit price-refresh work continues independently as requested.

Three added regression tests reproduce the mylist/API, detail-response race and storage-recovery failures. The detail race is also exercised in the real headless browser with a delayed response.

## Verification

- 82 Web/API/history/valuation/storage/CSV/navigation/localization/common-tab tests passed, including JST boundaries, delayed history, exclusions/restoration, migrations, backup recovery and purchase worker lifecycle.
- Headless Edge: 19 populated-server flows passed, with zero uncaught JavaScript errors. Menus, five history views, late detail responses, outside-click closing, CSV preset/download, list creation and narrow history-file UI were exercised. External services were intercepted.
- Layout: 15 theme/viewport combinations passed at 1920, 1280, 768, 390 and 320 px, with aligned summary cards and no clipped financial/count values or horizontal overflow.
- Native persistence: 14 checks passed. Seven commits wrote 664 logical primary payload bytes, 664 temporary payload bytes and 1,406 backup-copy bytes. Unchanged saves add zero commits. These are application counters, not SSD physical writes.
- Host lifecycle: 14 checks passed, including adoption/restart, unexpected exit, explicit stop, disposal, actual parent exit and reuse without duplicates. The independent server intentionally survives game exit.
- Localization: 680 checks over 42 complete keys; fonts: 44 lifecycle checks. Release build: zero warnings/errors. No translation keys or shared templates changed. StandardHistoryFilesTab.cs remains byte-identical to the canonical template.
- CSV revisions are computed from current in-memory state; no additional file reads, external requests or saves were introduced. Four export endpoints return stable revisions for unchanged repeated requests, and changed revisions after exclusion changes. The storage recovery test confirms no extra rendering for unchanged data.
- Package validation covers bundled runtime, browser modules, seven dictionaries, version/manifest URLs and exclusion of user data.

## Limits

This regression run cannot guarantee absence of every bug. Live-game rendering/login/logout timing, live Lodestone/market service behavior, prolonged production-scale operation and physical SSD writes remain unverified. No production migration, installed-file replacement, OS monitoring or automatic startup was introduced.
